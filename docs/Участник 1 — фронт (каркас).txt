=========================================================
УЧАСТНИК 1 - ФРОНТЕНД: КАРКАС И АВТОРИЗАЦИЯ
=========================================================
Проект: todo-приложение (фронт на TypeScript + бэк на Kotlin + база PostgreSQL).
Твоя часть: каркас приложения, авторизация на клиенте, все запросы к API,
роутинг и защита страниц.

Ссылка на репозиторий: https://github.com/dodry-question/todo-app-ts

---------------------------------------------------------
1. ЧТО СКАЧАТЬ
---------------------------------------------------------
1) Node.js LTS (вместе с npm) ....... https://nodejs.org
2) Git ............................. https://git-scm.com/download/win
3) Редактор кода (например, VS Code) ... https://code.visualstudio.com

Больше ничего не нужно.

---------------------------------------------------------
2. ПРОВЕРИТЬ, ЧТО ВСЁ ВСТАЛО
---------------------------------------------------------
Открой PowerShell и выполни по очереди:

   node -v
   npm -v
   git --version

Все три команды должны показать версию, а не ошибку.

---------------------------------------------------------
3. ЗАБРАТЬ ПРОЕКТ И СОЗДАТЬ СВОЮ ВЕТКУ
---------------------------------------------------------
   git clone https://github.com/dodry-question/todo-app-ts
   cd todo-app-ts
   git checkout -b frontend-core

(в ветке main напрямую не работаем)

---------------------------------------------------------
4. УСТАНОВИТЬ ЗАВИСИМОСТИ (делается один раз)
---------------------------------------------------------
Из папки frontend:

   npm install react react-dom react-router-dom

   npm install -D vite @vitejs/plugin-react typescript @types/react @types/react-dom @types/node

Папка node_modules появится сама, в git она не попадает.

---------------------------------------------------------
5. СНАЧАЛА - ДОГОВОР С БЭКОМ (ЭТО ПЕРВОЕ ДЕЛО)
---------------------------------------------------------
Миша заполняет docs/api.md: поля запросов и ответов, единый формат ошибок,
как передаётся токен. Ты подтверждаешь, что формат удобен фронту,
и сверяешь с ним frontend/src/types.ts (названия полей должны совпадать).
Пока в docs/api.md нет примеров JSON - оба фронта пишут «на угад».

---------------------------------------------------------
6. ЗАПУСТИТЬ ФРОНТ У СЕБЯ
---------------------------------------------------------
   cd frontend
   npm run dev

Адрес откроется в выводе команды (обычно http://localhost:5173).
Скрипты запуска (dev, build, preview) в package.json добавляешь ты -
этот файл твой (Петя их не правит).

---------------------------------------------------------
7. ТВОИ ФАЙЛЫ (только их и правишь)
---------------------------------------------------------
   frontend/package.json            скрипты запуска и зависимости
   frontend/tsconfig.json
   frontend/vite.config.ts
   frontend/src/main.tsx
   frontend/src/App.tsx             маршруты /login, /register, /
   frontend/src/api.ts              все запросы к API
   frontend/src/auth.tsx            токен, сессия, защита страниц
   frontend/src/types.ts            типы данных - совпадают с docs/api.md
   frontend/src/pages/LoginPage.tsx
   frontend/src/pages/RegisterPage.tsx

Полный список задач с галочками: файл docs/plan.md, раздел "Участник 1".

---------------------------------------------------------
8. ЧТО ДОЛЖНО ПОЛУЧИТЬСЯ
---------------------------------------------------------
- маршруты /login, /register, / и переходы между ними
- без токена на / не пускает, отправляет на /login
- с токеном открывается список задач
- после перезагрузки страницы пользователь остаётся залогиненным
- страница входа: email, пароль, ссылка на регистрацию, показ ошибки
- страница регистрации: имя, email, пароль, подтверждение пароля, показ ошибки
- кнопка «Выйти» чистит сессию и возвращает на вход
- все запросы к API идут через api.ts (адреса /api/auth/* и /api/tasks/*)

---------------------------------------------------------
