# План проекта и роли

**Что делаем:** todo-приложение с авторизацией. Пользователь регистрируется/входит и видит только свои задачи:
создать, изменить, отметить «выполнено», удалить.

**Стек:** фронтенд — TypeScript (React + Vite); бэкенд — Kotlin (Ktor + Exposed); база — PostgreSQL; всё в Docker.
Полные требования — в задании (PDF).

## Главное правило (чтобы всё точно запустилось)

Один фронтенд, **один бэкенд**, одна база — и ничего больше. Никаких вторых сервисов и второго бэкенда:
у фронта один адрес API, и `docker compose up` должен поднимать ровно три контейнера (фронт, бэк, база).
Если хочется написать «свой вариант» бэкенда — не в этом репозитории, чтобы не сломать запуск у всех.

## Порядок работы

1. **Договор API.** Миша заполняет `docs/api.md`, участники 1 и 4 подтверждают, что им так удобно. Без этого код не пишем.
2. **Код параллельно.** Фронт (участники 1 и 4) и бэк (участники 2 и Миша) пишутся одновременно — договорились, значит не мешаем друг другу.
3. **Docker.** Участник 5 собирает всё вместе и добивается запуска одной командой.
4. **Проверка.** Все вместе проходим чек-лист ниже. Если пункт не проходит — чиним его, пока не пройдёт.

## Правила работы в репозитории

1. Каждый работает в своей ветке и сливает в `main` через pull request (или через кнопку «Merge» на GitHub).
2. В `main` напрямую не коммитим.
3. Файлы из чужой зоны не правим. Нужно поменять — пишешь владельцу файла.
4. `.env`, пароли, токены и ключи в репозиторий не попадают.
5. Перед пушем — `git pull`, иначе перетрём чужое.
6. Не получилось — пишем в общий чат, не сидим молча.

## Чек-лист «всё запускается» (проверяем перед сдачей)

- [ ] `docker compose up` поднимает фронт, бэк и базу на чистой машине, без установки других программ
- [ ] фронт открывается в браузере, бэк отвечает
- [ ] можно зарегистрироваться, потом войти, потом выйти
- [ ] после перезагрузки страницы пользователь остаётся авторизованным
- [ ] незалогиненного на страницу задач не пускает, отправляет на вход
- [ ] задача создаётся, редактируется, отмечается выполненной, удаляется
- [ ] второй пользователь не видит задачи первого
- [ ] чужую задачу изменить/удалить нельзя
- [ ] ошибки показываются пользователю текстом, а не белым экраном
- [ ] `README.md` написан так, что запуск может повторить человек со стороны
